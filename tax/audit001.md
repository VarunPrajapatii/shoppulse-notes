The service uses calendar days in India time. `D:\study\ShopPulseAdmin\src\lib\tax\identity\registration-service.ts:78`, `:182`, `:731`, `D:\study\ShopPulseAdmin\src\lib\tax\fy.ts`. Bounds below are inclusive, and the current-period floor described below also applies.

- Not registered → regular, or not registered → composition: no separate backdate limit, but not earlier than the current period's start. Regular → composition: only 1 April, not before today, and no more than 90 days ahead. Source `registration-service.ts:189`.
- Composition → regular voluntarily: no earlier than today minus seven days; registration cancellation: no earlier than today minus 30 days. New GSTIN or unregistered identity change: no earlier than today. All transition types have the same maximum of today plus 90 days. Source `registration-service.ts:197`.
- Exact server reasons for a date outside the type-specific minimum: “The effective date cannot be before {YYYY-MM-DD} for this change.”; above the future maximum: “The effective date can be at most 90 days ahead.”; wrong date for regular → composition: “Moving from regular GST to composition starts only on 1 April.” Multiple reasons can be returned. Source `registration-service.ts:753`.
- A transition cannot start before the current row. It can replace the current row on the exact same start day only if **no order and no tax document reference that row**; otherwise it must start later. The row is actually deleted and replaced in the unreferenced case. Refusal: “The effective date must be after {YYYY-MM-DD}, when your current status started.” Source `registration-service.ts:215`, `:771`, `:852`.
- Only one future change: “A change is already scheduled. Delete it first to plan a different one.” Invalid effective date: “The effective date is invalid.” Deleting a change can return “This change was not found.”, “This change is already in effect.”, “Only the latest scheduled change can be deleted.” or “Orders or documents already use this change.” Source `registration-service.ts:735`, `:747`, `:902`.
- **First setup differs:** a registered certificate date can be past, but future is capped at 90 days; error “Registration date is invalid.” or “Registration date can be at most 90 days ahead.” The first record starts on the store's creation day, so a certificate earlier than creation does not make the store's stored period begin earlier than creation. Source `registration-service.ts:425`, `:501`.
