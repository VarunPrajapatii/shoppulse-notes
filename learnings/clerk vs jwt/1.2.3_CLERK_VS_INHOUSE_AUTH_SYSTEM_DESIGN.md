## 🌐 Edge Runtime Deep Dive

### **What is Edge Runtime?**

```
Traditional Server (Node.js)              Edge Runtime
┌────────────────────────────┐            ┌────────────────────────────┐
│  Location: Single region   │            │  Location: Global (50+ POPs)│
│  Startup: 100-500ms        │            │  Startup: <1ms              │
│  Modules: All Node.js      │            │  Modules: Limited subset    │
│  Size limit: No limit      │            │  Size limit: 1 MB           │
│  Database: Any (Prisma)    │            │  Database: HTTP-based only  │
│  Use case: Backend logic   │            │  Use case: Auth, routing    │
└────────────────────────────┘            └────────────────────────────┘

User in Tokyo                              User in Tokyo
  ↓                                          ↓
  Travels to US server (200ms)              Nearest edge: Tokyo (5ms)
  ↓                                          ↓
  Process request (50ms)                    Process at edge (2ms)
  ↓                                          ↓
  Return (200ms)                            Return to user (5ms)
  
Total: ~450ms                               Total: ~12ms
```

### **Middleware Edge Runtime Problem (ShopPulse)**

```typescript
// The Problem:
// ============

// File: src/middleware.ts (runs in edge runtime)
import { clerkMiddleware } from '@clerk/nextjs/server';
import prismadb from '@/lib/prismadb';  // ❌ 10-30 MB!

export default clerkMiddleware(async (auth, req) => {
  const { userId } = await auth();
  
  // ❌ This doesn't work in edge runtime!
  const user = await prismadb.user.findUnique({
    where: { id: userId },
    include: { subscription: true }
  });
  
  // Error: "Edge Function exceeds 1 MB limit"
});

// Why this fails:
// - Prisma Client: ~10-30 MB (includes query engine)
// - Native binaries: Requires Node.js runtime
// - Edge limit: 1 MB total bundle size
// - Result: Deployment fails ❌

// Solutions:
// ==========

// Solution 1: Wrapper pattern (recommended for ShopPulse)
// Keep middleware simple, check subscription in handler
export default clerkMiddleware(async (auth, req) => {
  const { userId } = await auth();
  
  if (!userId) {
    return NextResponse.redirect('/login');
  }
  
  // ✅ No Prisma import, no database query
  return NextResponse.next();
});

// In handler (Node.js runtime):
export async function GET(req: Request) {
  const { userId } = await auth();
  
  // ✅ Now we can use Prisma (not in edge)
  const user = await prismadb.user.findUnique({
    where: { id: userId },
    include: { subscription: true }
  });
  
  if (!user.isActive) {
    return NextResponse.json({ error: 'Expired' }, { status: 402 });
  }
  
  // Process request...
}

// Solution 2: Hybrid (Clerk + Redis)
// Check subscription at edge without Prisma
import { Redis } from '@upstash/redis';  // ✅ Edge-compatible

const redis = Redis.fromEnv();

export default clerkMiddleware(async (auth, req) => {
  const { userId } = await auth();
  
  // ✅ Query Redis instead of PostgreSQL
  const subscription = await redis.get(`user:${userId}:sub`);
  
  if (!subscription || subscription.status === 'EXPIRED') {
    return NextResponse.json({ error: 'Expired' }, { status: 402 });
  }
  
  return NextResponse.next();
});

// Solution 3: In-house JWT
// Store subscription in token claims
import { jwtVerify } from 'jose';  // ✅ Edge-compatible

export async function middleware(req: NextRequest) {
  const token = req.cookies.get('session')?.value;
  
  const secret = new TextEncoder().encode(process.env.JWT_SECRET);
  const { payload } = await jwtVerify(token, secret);
  
  // ✅ Check subscription from claims (no database!)
  if (payload.subscriptionStatus === 'EXPIRED') {
    return NextResponse.json({ error: 'Expired' }, { status: 402 });
  }
  
  return NextResponse.next();
}
```

### **Edge vs Node.js Runtime Decision Tree**

```
Should this code run in edge runtime?
│
├─ Does it need database queries? (Prisma)
│  └─ YES → Use Node.js runtime (handler)
│  └─ NO  → Continue to next question
│
├─ Does it need filesystem access?
│  └─ YES → Use Node.js runtime
│  └─ NO  → Continue to next question
│
├─ Does it need native modules?
│  └─ YES → Use Node.js runtime
│  └─ NO  → Continue to next question
│
├─ Is bundle size < 1 MB?
│  └─ NO  → Use Node.js runtime
│  └─ YES → Continue to next question
│
├─ Is low latency critical? (<10ms)
│  └─ YES → Use edge runtime ✅
│  └─ NO  → Either runtime works
│
└─ Use edge runtime for:
   ├─ Authentication (Clerk, JWT verify)
   ├─ Authorization (if using Redis/JWT)
   ├─ Rate limiting (if using Redis)
   ├─ Request routing
   └─ Header manipulation
   
   Use Node.js runtime for:
   ├─ Database queries (Prisma)
   ├─ Complex business logic
   ├─ File processing
   └─ Third-party API calls (with retries)
```

          // Redis sorted set
