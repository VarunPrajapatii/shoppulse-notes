## Razorpay Subscription System Overview

> **✅ IMPL STATUS: IMPLEMENTED** — Schema has `SubscriptionPlan` model with `razorpayPlanId` and `Subscription` model with `razorpaySubscriptionId` in `prisma/schema.prisma`. The UPDATE API correction mentioned below is the approach actually in production.

### What Razorpay Provides

Razorpay's subscription system is built around **plans** and **subscriptions**:

```
Plan (Template)
├─ Billing Cycle (monthly, yearly, etc.)
├─ Price
├─ Total Count (number of billing cycles)
└─ Created once, reused for multiple customers

Subscription (Instance)
├─ Links: Customer + Plan
├─ Tracking: paid_count, remaining_count
├─ Lifecycle: authenticated → charged → completed
└─ One per customer per plan
```

- You CAN change plan_id using `subscriptions.update()` API
- Razorpay handles proration automatically
- Same subscription ID is preserved
- See Part 23 (Update Subscription) documentation

When user changes plans, use the **UPDATE API**:
1. Call `razorpay.subscriptions.update(id, { plan_id, schedule_change_at })`
2. Razorpay calculates proration automatically
3. Razorpay charges the correct amount
4. Same subscription ID preserved
5. Listen for `subscription.updated` webhook

### Proration Calculation Library
<!-- NOTE: we need to see the exact implementation for proration to notify user -->
```typescript
// lib/proration-calculator.ts

import { BillingCycle } from '@/generated/prisma';
import { differenceInDays, differenceInHours } from 'date-fns';

/**
 * Get total days in a billing cycle
 */
function getBillingCycleDays(cycle: BillingCycle): number {
  switch (cycle) {
    case 'MONTHLY':
      return 30;
    case 'HALFYEARLY':
      return 180;
    case 'YEARLY':
      return 365;
    default:
      throw new Error(`Unknown billing cycle: ${cycle}`);
  }
}

/**
 * Calculate prorated credit for unused time
 * 
 * @param planPrice - Original plan price (in rupees)
 * @param billingCycle - MONTHLY, HALFYEARLY, or YEARLY
 * @param currentPeriodEnd - End of current billing period
 * @returns Credit amount in rupees (2 decimal places)
 */
export function calculateProrationCredit(
  planPrice: number,
  billingCycle: BillingCycle,
  currentPeriodEnd: Date
): number {
  const now = new Date();
  
  // If period already ended, no credit
  if (currentPeriodEnd <= now) {
    return 0;
  }
  
  // Calculate days remaining
  const daysRemaining = differenceInDays(currentPeriodEnd, now);
  
  // Include partial day (hours)
  const hoursRemaining = differenceInHours(currentPeriodEnd, now);
  const fractionalDays = hoursRemaining / 24;
  
  // Total days in cycle
  const totalDays = getBillingCycleDays(billingCycle);
  
  // Calculate credit
  const credit = planPrice * (fractionalDays / totalDays);
  
  // Round to 2 decimal places
  return Math.round(credit * 100) / 100;
}

/**
 * Calculate charge amount for plan change
 * 
 * @param oldPlan - Current plan details
 * @param newPlan - New plan details
 * @param currentPeriodEnd - End of current billing period
 * @returns Object with credit and charge amount
 */
export function calculatePlanChangeCharge(
  oldPlan: {
    price: number;
    billingCycle: BillingCycle;
  },
  newPlan: {
    price: number;
    billingCycle: BillingCycle;
  },
  currentPeriodEnd: Date
): {
  credit: number;
  chargeAmount: number;
  isUpgrade: boolean;
  isDowngrade: boolean;
  daysRemaining: number;
} {
  // Calculate credit from old plan
  const credit = calculateProrationCredit(
    oldPlan.price,
    oldPlan.billingCycle,
    currentPeriodEnd
  );
  
  // New plan full price
  const newPlanPrice = newPlan.price;
  
  // Charge = new price - credit
  const chargeAmount = Math.max(0, newPlanPrice - credit);
  
  // Determine if upgrade or downgrade
  const isUpgrade = newPlanPrice > oldPlan.price;
  const isDowngrade = newPlanPrice < oldPlan.price;
  
  // Days remaining
  const daysRemaining = Math.max(0, differenceInDays(currentPeriodEnd, new Date()));
  
  return {
    credit: Math.round(credit * 100) / 100,
    chargeAmount: Math.round(chargeAmount * 100) / 100,
    isUpgrade,
    isDowngrade,
    daysRemaining
  };
}

/**
 * Calculate credit to apply for downgrade (no refund policy)
 * 
 * @param oldPlan - Current plan details
 * @param newPlan - New plan details (lower price)
 * @param currentPeriodEnd - End of current billing period
 * @returns Credit to add to user account
 */
export function calculateDowngradeCredit(
  oldPlan: {
    price: number;
    billingCycle: BillingCycle;
  },
  newPlan: {
    price: number;
    billingCycle: BillingCycle;
  },
  currentPeriodEnd: Date
): {
  credit: number;
  monthsCovered: number;
  daysRemaining: number;
} {
  // Get unused value from old plan
  const unusedValue = calculateProrationCredit(
    oldPlan.price,
    oldPlan.billingCycle,
    currentPeriodEnd
  );
  
  // Calculate how many months of new plan this covers
  const monthsCovered = unusedValue / newPlan.price;
  
  const daysRemaining = Math.max(0, differenceInDays(currentPeriodEnd, new Date()));
  
  return {
    credit: Math.round(unusedValue * 100) / 100,
    monthsCovered: Math.round(monthsCovered * 10) / 10, // 1 decimal
    daysRemaining
  };
}

/**
 * Get human-readable proration explanation
 */
export function getProrationExplanation(
  oldPlan: { price: number; billingCycle: BillingCycle; displayName: string },
  newPlan: { price: number; billingCycle: BillingCycle; displayName: string },
  currentPeriodEnd: Date
): string {
  const calc = calculatePlanChangeCharge(oldPlan, newPlan, currentPeriodEnd);
  
  if (calc.isUpgrade) {
    return `
You'll be charged ₹${calc.chargeAmount.toFixed(2)} today:
• ${newPlan.displayName}: ₹${newPlan.price}
• Credit for ${calc.daysRemaining} days unused on ${oldPlan.displayName}: -₹${calc.credit.toFixed(2)}
• Total: ₹${calc.chargeAmount.toFixed(2)}

Your new subscription starts immediately and lasts ${getBillingCycleDays(newPlan.billingCycle)} days.
    `.trim();
  }
  
  if (calc.isDowngrade) {
    const downgradeCalc = calculateDowngradeCredit(oldPlan, newPlan, currentPeriodEnd);
    return `
You have ${calc.daysRemaining} days remaining on ${oldPlan.displayName}.

Option 1 (Recommended): Schedule Downgrade
• Keep ${oldPlan.displayName} features until ${currentPeriodEnd.toLocaleDateString()}
• Switch to ${newPlan.displayName} at renewal
• No charge today

Option 2: Immediate Downgrade with Credit
• Unused value: ₹${downgradeCalc.credit.toFixed(2)}
• Applied as account credit
• Covers ${downgradeCalc.monthsCovered.toFixed(1)} months of ${newPlan.displayName}
• Next charge: After credit exhausted
    `.trim();
  }
  
  return `No charge difference detected.`;
}
```

**Use subscriptions.update()**

**What Happens (Officially)**:
1. **Razorpay Calculates Proration**:
   - Detects unused time on old plan
   - Calculates credit value

2. **Automatic Charge**:
   - Razorpay charges difference amount to saved payment method
   - No checkout page needed (uses existing authorization)
   - User sees charge on their statement

3. **Subscription Updated**:
   - Same subscription ID (e.g., `sub_00000000000001`)
   - Plan changes immediately
   - Status: Stays `active`
   - Webhook fires: `subscription.updated`

4. **Next Charge (New plan period end date)**:
   - Razorpay auto-charges
   - Uses existing auto-pay authorization

**When to Use**:
- ✅ Plan upgrades (MINI → MAXI)
- ✅ Plan downgrades (MAXI → MIDI)
- ✅ Immediate or scheduled changes
- ✅ Quantity changes (add/remove seats)

**Limitations**:
- ❌ Cannot update UPI/Emandate subscriptions (must cancel + create new)
- ❌ Only works on `authenticated` or `active` subscriptions

### Understanding Razorpay UPDATE vs CREATE

> **✅ IMPL STATUS: IMPLEMENTED (UPDATE path only)** — Only the UPDATE path is in production. For UPI/Emandate payment methods where UPDATE fails, our upgrade route at `src/app/api/subscription/upgrade/execute/route.ts` (lines ~387-419) does the following:
> 
> **Our UPI/Emandate Handling:**
> 1. The code calls `subscriptions.update()` first (letting Razorpay be source of truth for what's supported)
> 2. When Razorpay returns `BAD_REQUEST_ERROR` with "upi" or "card mandate" in the description, the error handler catches it
> 3. Returns `{ errorCode: 'PAYMENT_METHOD_NOT_SUPPORTED', requiresCancelFlow: true, suggestion: "... cannot be upgraded directly. You can cancel your current subscription and subscribe to the new plan." }`
> 4. The API does **NOT auto-cancel** — it tells the frontend the user must cancel and re-subscribe manually
> 5. No CREATE-for-plan-change fallback is implemented — user must go through the standard cancel → create → checkout → verify flow

**Critical Difference**: When to update vs when to create new subscription.

**UPDATE API (Recommended for Plan Changes)**

**CREATE API (When UPDATE Won't Work)**:

```javascript
// Use CREATE only when UPDATE is not possible
// Note: customer_id is NOT a create param (Razorpay auto-creates customer)
const newSub = await razorpay.subscriptions.create({
  plan_id: 'plan_newPlan',
  total_count: 6,
  start_at: Math.floor(Date.now() / 1000),
  customer_notify: true
});
```

**When to Use CREATE**:
- ❌ UPI/Emandate subscriptions (cannot be updated)
- ❌ Expired subscriptions (must create fresh)
- ❌ Cancelled subscriptions (if too old)
- ❌ Creating first subscription for a new customer

**Timeline Comparison**:

**UPDATE API Flow:**
```

  ↓
Call subscriptions.update()
  ↓

  ↓
subscription.updated webhook fires
```

### Limitation 2: Customer Data in Razorpay

**Problem**: Customer data (email, name) in Razorpay separate from subscription.

**Workaround**: Always link via `customer_id` stored in your DB.

**Schema**:
```prisma
model Subscription {
  id                     String @id
  razorpaySubscriptionId String @unique
  razorpayCustomerId     String // ← Store this!
  razorpayPlanId         String
  // ...
}
```

**Usage**:
```typescript
// Always fetch customer when changing plans
const subscription = await prisma.subscription.findUnique({
  where: { id: subscriptionId },
  select: { razorpayCustomerId: true }
});

const newSub = await razorpay.subscriptions.create({
  plan_id: newPlanId,
  customer_id: subscription.razorpayCustomerId, // ← Reuse same customer
  // ...
});
```
