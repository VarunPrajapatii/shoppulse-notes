## Reactivation Scenarios Overview

> **❌ IMPL STATUS: NOT IMPLEMENTED (as dedicated feature)** — No `/api/subscription/reactivate` route exists. `REACTIVATED` action exists in `SubscriptionAction` enum. Webhook `resumed.ts` handles Razorpay-side resume for paused subs, but no user-facing API for un-cancel.
> **✂️ KEEP (trimmed)** — Overview table and status-based logic valuable for implementing this feature. Delete verbose user stories.

### What is Reactivation?

**Reactivation** = User previously canceled subscription, now wants it back

**Statuses that can reactivate**:
- `CANCELED` - User canceled but period hasn't ended yet (can keep same plan or upgrade) (once cancled cant be reactivated, dont know about Razorpay's cancle at period end).
- `EXPIRED` - Subscription already ended (must create new subscription)

**Statuses that CANNOT reactivate**:
- `PAST_DUE` - Payment failed (fix payment, don't reactivate)
- `COMPLETING` - Special status, handle separately

---

### Reactivation Types

| Type | Description | Credit Handling |
|------|-------------|-----------------|
| **Same Plan** | Cancel cancellation, resume current plan | No credit (already paid) |
| **Upgrade** | Cancel + switch to higher plan | Calculate proration from remaining days |
| **Downgrade** | Not recommended (user already canceling) | Block or schedule for next period |
| **New Plan** | After EXPIRED, create fresh subscription | No credit (clean slate) |

### Common User Stories

**Story 1**: "I canceled but changed my mind"
- Status: `CANCELED`
- Days remaining: 15

**Story 2**: "I canceled but now I need more features"

- Credit: Calculate 15 days × old plan price, apply to new plan

**Story 3**: "My subscription expired, I want to come back"
- Status: `EXPIRED`
- Days remaining: 0
- Action: Create new subscription
- Credit: None
- Implementation: Normal signup flow

### 1. Resume Same Plan (Cancel Cancellation)

```typescript
// src/app/api/subscription/reactivate/route.ts

import { NextResponse } from 'next/server';
import { auth } from '@clerk/nextjs/server';
import prisma from '@/lib/prismadb';
import razorpay from '@/lib/razorpay';

export async function POST(req: Request) {
  try {
    const { userId: clerkId } = await auth();
    if (!clerkId) {
      return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
    }
    
    // Get user's subscription
    const user = await prisma.user.findUnique({
      where: { id: clerkId },
      include: {
        subscription: {
          include: { plan: true }
        }
      }
    });
    
    if (!user?.subscription) {
      return NextResponse.json(
        { error: 'No subscription found' },
        { status: 400 }
      );
    }
    
    const subscription = user.subscription;
    
    // Can only reactivate CANCELED subscriptions
    if (subscription.status !== 'CANCELED') {
      return NextResponse.json(
        { error: `Cannot reactivate ${subscription.status} subscription` },
        { status: 400 }
      );
    }
    
    // Check if period hasn't ended yet
    if (subscription.currentPeriodEnd < new Date()) {
      return NextResponse.json(
        { error: 'Subscription period already ended. Please create a new subscription.' },
        { status: 400 }
      );
    }
    
    // Reactivate in Razorpay
    let razorpayReactivated = false;
    
    if (subscription.razorpaySubscriptionId) {
      try {
        // Check if Razorpay subscription still exists
        const razorpaySub = await razorpay.subscriptions.fetch(
          subscription.razorpaySubscriptionId
        );
        
        // If canceled at cycle end, we can't reactivate in Razorpay
        // User will auto-renew at period end
        if (razorpaySub.status === 'cancelled') {
          console.warn('⚠️ Razorpay subscription already canceled');
        } else {
          // Update to not cancel at cycle end
          await razorpay.subscriptions.update(
            subscription.razorpaySubscriptionId,
            {
              schedule_change: {
                cancel: false
              }
            }
          );
          razorpayReactivated = true;
          console.log(`✅ Reactivated subscription in Razorpay`);
        }
      } catch (error) {
        console.error('❌ Razorpay reactivation error:', error);
        // Continue with DB update even if Razorpay fails
      }
    }
    
    // Update database
    await prisma.$transaction(async (tx) => {
      await tx.subscription.update({
        where: { id: subscription.id },
        data: {
          status: 'ACTIVE',
          canceledAt: null,
          metadata: {
            ...(subscription.metadata as any),
            reactivatedAt: new Date(),
            reactivationType: 'same_plan',
            razorpayReactivated
          },
          updatedAt: new Date()
        }
      });
      
      await tx.subscriptionHistory.create({
        data: {
          subscriptionId: subscription.id,
          action: 'REACTIVATED',
          fromStatus: 'CANCELED',
          toStatus: 'ACTIVE',
          reason: 'User reactivated canceled subscription',
          metadata: {
            type: 'reactivate_same_plan',
            razorpayReactivated,
            daysRemaining: Math.ceil(
              (subscription.currentPeriodEnd.getTime() - Date.now()) / (1000 * 60 * 60 * 24)
            )
          }
        }
      });
    });
    
    console.log(`✅ Reactivated subscription for ${user.email}`);
    console.log(`   Plan: ${subscription.plan.displayName}`);
    console.log(`   Access until: ${subscription.currentPeriodEnd.toDateString()}`);
    
    return NextResponse.json({
      success: true,
      message: 'Subscription reactivated successfully',
      details: {
        plan: subscription.plan.displayName,
        status: 'ACTIVE',
        accessUntil: subscription.currentPeriodEnd
      }
    });
    
  } catch (error) {
    console.error('❌ Reactivation error:', error);
    return NextResponse.json(
      { error: 'Failed to reactivate subscription' },
      { status: 500 }
    );
  }
}
```

## PAST_DUE Handling Strategies

> **✅ IMPL STATUS: IMPLEMENTED** — Grace period approach (Strategy 1) is fully implemented:
> - `src/app/api/cron/expire-trials-detect-payment-failure/route.ts` → detects payment failures, sets `PAST_DUE` + `paymentGracePeriod: true`
> - `src/app/api/webhook/razorpay/subscription/handlers/halted.ts` → after all retries fail, expires subscription
> - `paymentGracePeriod` field on User model in schema
> - `charged.ts` webhook clears grace period on successful payment
> - Razorpay's built-in retry mechanism (5-7 days) serves as the grace period

### Understanding PAST_DUE

**When does it happen?**
- Razorpay auto-charge fails (card declined, insufficient funds, expired card)
- User's payment method invalid

**Razorpay's behavior**:
- Marks subscription as `past_due`
- Retries payment automatically (configurable)

---

### Strategy 1: Grace Period (Recommended)

**Pros**:
✅ Better UX (user doesn't lose data immediately)
✅ Higher retention (time to fix payment)
✅ Industry standard (Netflix, Spotify do this)

**Cons**:
❌ Potential abuse
❌ More complex logic

---

### Strategy 2: Immediate Block

**Pros**:
✅ Simple logic
✅ No abuse potential
✅ Clear boundaries

**Cons**:
❌ Harsh UX
❌ Higher churn

### Retry Payment Implementation

> **❌ IMPL STATUS: NOT IMPLEMENTED** — No `/api/subscription/retry-payment` route exists.
> 
> **🔍 RAZORPAY MANUAL RETRY API RESEARCH (verified against official docs):**
> - **Razorpay does NOT offer any programmatic retry API for subscriptions.** There is no `subscriptions.charge()`, no `POST /subscriptions/:id/retry`, no manual charge endpoint.
> - **Retries are fully automatic:** Failed charge → PENDING state → Razorpay retries at T+1, T+2, T+3 days → If all fail → HALTED state
> - **Manual charge is Dashboard-only:** Navigate to Subscription → click invoice → click "Attempt Charge" (and domestic card manual charge is NOT supported!)
> - **Retry settings are configurable via Razorpay Dashboard Settings**, not API
> 
> **Our only programmatic options for PAST_DUE/HALTED recovery:**
> 1. ✅ Listen to webhooks (`subscription.pending`, `subscription.halted`) → notify user (IMPLEMENTED via cron + webhooks)
> 2. 🟡 Show "Update Payment Method" button using Razorpay Checkout with `subscription_card_change: true` (NOT YET IMPLEMENTED)
> 3. ✅ Wait for Razorpay's automatic retries during PENDING window (IMPLEMENTED — we do nothing, Razorpay retries)
> 4. ❌ There is NO API call to force-retry a payment

### Rollback Strategy

```typescript
// src/lib/rollback-subscription-change.ts

export async function rollbackSubscriptionChange(
  subscriptionId: string,
  reason: string
): Promise<void> {
  console.log(`🔄 Rolling back subscription change: ${subscriptionId}`);
  console.log(`   Reason: ${reason}`);
  
  // Get subscription with history
  const subscription = await prisma.subscription.findUnique({
    where: { id: subscriptionId },
    include: {
      history: {
        orderBy: { createdAt: 'desc' },
        take: 1
      }
    }
  });
  
  if (!subscription) {
    throw new Error('Subscription not found');
  }
  
  const lastHistory = subscription.history[0];
  
  if (!lastHistory) {
    console.warn('⚠️ No history to rollback to');
    return;
  }
  
  // Rollback to previous state
  await prisma.$transaction(async (tx) => {
    await tx.subscription.update({
      where: { id: subscriptionId },
      data: {
        planId: lastHistory.fromPlanId!,
        status: lastHistory.fromStatus!,
        updatedAt: new Date(),
        metadata: {
          ...(subscription.metadata as any),
          rolledBackAt: new Date(),
          rollbackReason: reason,
          rolledBackFromHistory: lastHistory.id
        }
      }
    });
    
    await tx.subscriptionHistory.create({
      data: {
        subscriptionId,
        action: 'REACTIVATED', // Rolled back
        fromPlanId: lastHistory.toPlanId,
        toPlanId: lastHistory.fromPlanId,
        fromStatus: lastHistory.toStatus,
        toStatus: lastHistory.fromStatus,
        reason: `Rollback: ${reason}`,
        metadata: {
          type: 'rollback',
          originalHistoryId: lastHistory.id
        }
      }
    });
  });
  
  console.log(`✅ Rollback complete`);
}
```
