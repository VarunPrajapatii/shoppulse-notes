## Critical Rules (Must Know!)

**📝 STATUS: ✅ ACCURATE** — Rule 1 (update creates invoice), Rule 3 (no subscription.charged webhook) — all correct and our code handles these appropriately.

### Rule 1: Update Creates Invoice (Not Regular Charge)
- Razorpay creates an **invoice** for the difference amount
- Charges the invoice automatically
- If charge succeeds → `subscription.updated` webhook fires
- If charge fails → Subscription stays on old plan (automatic rollback)

### Rule 3: No subscription.charged Webhook
⚠️ **Only `subscription.updated` fires for immediate upgrades**

Unlike regular billing cycles, upgrade charges don't trigger `subscription.charged`. The payment happens as part of the invoice created during the update process.

How Payment Authorization Actually Works (Industry Standard)
Based on payment gateway standards and Razorpay's behavior:

1. Card Mandate/Authorization
When customer creates a subscription (₹999/month):

Initial Authorization Flow:
1. Customer enters card details
2. Razorpay checks with bank: "Can we charge recurring payments?"
3. Bank authorizes: "Yes, for subscription amounts"
4. Razorpay stores card token for future charges

Key Point: The authorization is typically NOT amount-limited for cards.

### 🏛️ AUDIT (2025-07-19): RBI ₹15,000 Auto-Debit Threshold — CRITICAL ADDITION

While card tokens are NOT amount-capped by Razorpay, **RBI's recurring payment framework (Oct 2021)** imposes a real ceiling:

| Amount | Behavior |
|--------|----------|
| **≤ ₹15,000** | Auto-debit proceeds silently — no AFA (OTP) required |
| **> ₹15,000** | Bank **MUST** request AFA (OTP/biometric) from customer before debit |

Since the UPDATE API charges the card **in the background** (user isn't present), any charge > ₹15,000 will **fail silently** because the user can't enter OTP.

**For our plans:** Monthly ₹999 → Half-yearly ₹6,000 = ~₹5,300 charge → SAFE (below ₹15K).
Monthly ₹999 → Yearly ₹10,000 = ~₹9,300 → SAFE. But if we ever add premium plans > ₹15K/cycle, upgrades via UPDATE API will break.

**Also:** UPI and eMandate subscriptions **cannot be updated at all** (amount-specific mandates). Our LEARNING_4 fallback strategy (cancel + resubscribe) handles this.

2. What Happens During Upgrade (UPDATE API)

export async function POST(req: Request) {
  const { newPlanId } = await req.json();
  
  const user = await prisma.user.findUnique({
    where: { id: userId },
    include: { subscription: { include: { plan: true } } }
  });

  const currentSub = user.subscription;
  const newPlan = await prisma.subscriptionPlan.findUnique({
    where: { id: newPlanId }

  const chargeAmount = calculateChargeAmount(currentSub, newPlan);
