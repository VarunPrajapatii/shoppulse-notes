## Upgrade Scenarios Overview

**📝 IMPLEMENTATION STATUS:**
Our code only allows upgrade from `ACTIVE` status (execute/route.ts). CANCELED, COMPLETING, PAST_DUE, EXPIRED, PAUSED statuses are NOT allowed for upgrade. The scenario matrix here is more permissive than our implementation.

### Scenario Matrix

| Current Status | Can Upgrade? | Method | Special Handling |
|----------------|--------------|--------|------------------|
| **ACTIVE** | ✅ Yes | UPDATE API | Standard flow |
| **CANCELED** | ✅ Yes | CREATE new | If scheduled cancellation |
| **COMPLETING** | ✅ Yes | UPDATE API | Extends beyond period end |
| **PAST_DUE** | ⚠️ Maybe | After payment | Must clear dues first |
| **EXPIRED** | ❌ No | CREATE new | Must create new subscription |
| **PAUSED** | ❌ No | UPDATE API | Can update while paused |

### Scenario 1: ACTIVE → Higher Tier (Standard Upgrade)

**Example**:
```
User: Monthly plan (₹3,500), Day 10 of 30
Wants: Half-Yearly plan (₹18,000)

Calculation (for display only):
- Days remaining: 20
- Unused value: ₹3,500 × (20/30) = ₹2,333.33
- Expected charge: ₹18,000 - ₹2,333.33 = ₹15,666.67
- New period: Today → Today + 180 days

Steps (OFFICIAL UPGRADE FLOW):
1. Show user preview of upgrade (calculated proration for display)
2. User confirms upgrade
3. Call UPDATE API:
   await razorpay.subscriptions.update(subscriptionId, {
     plan_id: halfYearlyPlanId,
     schedule_change_at: 'now',
     customer_notify: true
   })
4. Razorpay automatically:
   - Calculates proration (₹2,333.33)
   - Charges ₹15,666.67 to saved payment method
   - Updates plan to Half-Yearly
   - Fires subscription.updated webhook
5. In webhook: Update database with new plan
6. User gets immediate access to new limits ✓

BENEFITS:
✅ Same subscription ID (no disruption)
✅ Razorpay calculates proration (accurate)
✅ No checkout page (seamless)
✅ Simpler webhook
✅ No manual cancellation needed
```

### Scenario 2B: CANCELED → Higher Tier (Upgrade + Reactivation)

**Example**:
```
User: Canceled Monthly plan (₹3,500), 15 days remaining
Wants: Half-Yearly plan (₹18,000)

NEW APPROACH (Official):
1. Check if subscription is still active in Razorpay
2. If yes (cancellation scheduled for cycle end):
   - Call UPDATE API:
     await razorpay.subscriptions.update(subscriptionId, {
       plan_id: halfYearlyPlanId,
       schedule_change_at: 'now'
     })
   - This also CANCELS the scheduled cancellation!
   - Subscription becomes ACTIVE with new plan

3. If no (already cancelled in Razorpay):
   - Must CREATE new subscription (UPDATE won't work)
   - Follow new subscription flow

Database Changes:
┌─────────────────────────────┬────────────────────┬─────────────────────┐
│ Field                       │ Before (CANCELED)  │ After (ACTIVE)      │
├─────────────────────────────┼────────────────────┼─────────────────────┤
│ planId                      │ monthly_plan_id    │ halfyearly_plan_id  │
│ status                      │ CANCELED           │ ACTIVE              │
│ razorpaySubscriptionId      │ sub_123 (SAME!)    │ sub_123 (SAME!)     │
│ razorpayPlanId              │ plan_monthly       │ plan_halfyearly     │
│ currentPeriodStart          │ Nov 1              │ Nov 18 (today)      │
│ currentPeriodEnd            │ Nov 30             │ May 17 (today+180)  │
│ canceledAt                  │ Nov 10             │ null                │
│ cancelAtPeriodEnd           │ true               │ false               │
│ autoRenew                   │ false              │ true                │
└─────────────────────────────┴────────────────────┴─────────────────────┘
```

## Complete End-to-End Flow

### User Journey (Upgrade)

```
1. User Dashboard
   └─> Click "Upgrade to Half-Yearly"

2. Preview Dialog Opens
   ├─> API call: POST /api/subscription/upgrade/preview
   ├─> Shows:
   │   ├─ Current plan: Monthly (₹3,500)
   │   ├─ New plan: Half-Yearly (₹18,000)
   │   ├─ Days remaining: 20
   │   ├─ Credit: ₹2,333.33
   │   └─ Amount to charge: ₹15,666.67
   └─> User clicks "Confirm Upgrade"

3. Backend Processing
   ├─> API call: POST /api/subscription/upgrade/execute
   ├─> Validates subscription status
   ├─> Calls Razorpay UPDATE API:
   │   razorpay.subscriptions.update(subId, {
   │     plan_id: newPlanId,
   │     schedule_change_at: 'now'
   │   })
   ├─> Razorpay:
   │   ├─ Calculates proration automatically
   │   ├─ Charges ₹15,666.67 to saved payment method
   │   ├─ Updates subscription plan
   │   └─ Fires subscription.updated webhook
   └─> Returns success

4. Webhook Processing
   ├─> Receives: subscription.updated event
   ├─> Updates database:
   │   ├─ planId: monthly → halfyearly
   │   ├─ status: ACTIVE
   │   ├─ currentPeriodEnd: +180 days
   │   └─ Clear scheduled changes
   ├─> Creates history record
   └─> Invalidates cache

5. User Experience
   ├─> Sees success message: "Upgrade successful!"
   ├─> Page refreshes
   ├─> Dashboard shows: Half-Yearly plan
   ├─> New limits immediately available
   └─> No checkout page needed ✓

Benefits:
✅ Seamless (no checkout)
✅ Instant (no waiting)
✅ Accurate (Razorpay calculates)
✅ Simple (50 lines of webhook code vs 163)
✅ Safe (same subscription ID, no dual subscriptions)
```
