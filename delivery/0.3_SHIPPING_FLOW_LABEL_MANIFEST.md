## 1. What Are Labels & Manifests?

### Shipping Label 📦

**What it is:** A sticker with barcode, addresses, and order info that goes ON THE PACKAGE.

```
┌─────────────────────────────────────────────────────────┐
│  ┌───────────────┐                                      │
│  │ ▓▓▓▓▓▓▓▓▓▓▓▓▓ │  AWB: 789456123456                  │
│  │ ▓▓▓▓▓▓▓▓▓▓▓▓▓ │  Courier: Delhivery                 │
│  └───────────────┘                                      │
│                                                         │
│  FROM: Fashion Store                                    │
│        123 Warehouse St, Mumbai 400001                  │
│                                                         │
│  TO:   Rahul Kumar                                      │
│        456 Apartment Lane, Apt 12B                      │
│        Delhi 110001                                     │
│        Phone: 9876543210                                │
│                                                         │
│  Order: #ORD-2026-1234                                  │
│  Weight: 0.5 kg | COD: ₹1,299                          │
│                                                         │
│  ┌───────────────────────────────────────────────────┐ │
│  │ ████ ███ ████ ██ ████ ███ ██ ████ ███ ████       │ │
│  └───────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

**Purpose:**
- Courier scans barcode to track package
- Shows delivery address
- Contains payment info (COD amount)

**Generated by:** Shiprocket API (`POST /courier/generate/label`)

### Manifest Document 📋

**What it is:** A summary document listing ALL shipments for a pickup. Given to courier during pickup.

```

│                           PICKUP MANIFEST                                   │
│                       Fashion Store - Jan 14, 2026                          │

│  Pickup Token: PK-2026-789456                                              │

│  Total Weight: 15.5 kg                                                      │

## 2. When Are They Generated?

### Timeline

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          DOCUMENT GENERATION TIMELINE                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  Step 1: Create Shipment                                                    │
│  └─ AWB assigned by Shiprocket                                             │
│                                                                             │
│  Step 2: LABEL GENERATED ← Immediate                                        │
│  └─ Available as soon as AWB is assigned                                   │
│  └─ Seller should print NOW and stick on package                           │
│                                                                             │
│  Step 3: Add to Pickup Queue                                                │
│  └─ Status: PICKUP_QUEUED                                                  │
│                                                                             │
│  Step 4: Cron Schedules Pickup                                              │
│  └─ Status: PICKUP_SCHEDULED                                               │
│                                                                             │
│  Step 5: MANIFEST GENERATED ← After pickup scheduled                       │
│  └─ Contains all shipments for this pickup batch                           │
│  └─ Seller prints before courier arrives                                   │
│                                                                             │
│  Step 6: Courier Arrives                                                    │
│  └─ Seller hands over packages + manifest                                  │
│  └─ Courier signs manifest                                                 │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Key Insight: Labels Are Per-Order, Manifests Are Per-Pickup-Batch

| Document | Quantity | When Generated | Who Needs It |
|----------|----------|----------------|--------------|
| **Label** | 1 per order | Immediately after AWB | Seller (stick on box) |
| **Manifest** | 1 per pickup batch | After pickup scheduled | Seller + Courier (handover proof) |

## 3. Industry Standard: How Big Players Do It

### Amazon Seller Central

**Label Download:**
- Batch download available: "Download all labels" button
- Downloads as **multi-page PDF** (1 label per page)
- Seller prints all pages, cuts/separates, sticks on boxes

**How sellers match labels to boxes:**
- Each label has ORDER ID prominently displayed
- Seller packs items, writes order ID on box with marker
- After printing batch labels, matches by order ID

### Flipkart Seller Hub

**Label Download:**
- Same: batch download as multi-page PDF
- Option: "Print in 4-up format" (4 labels per page, smaller)

### Myntra Partner Portal

**Label Download:**
- Batch download with **filename as Order ID**
- Downloads ZIP file with individual PDFs
- `ORD-2026-1234.pdf`, `ORD-2026-1235.pdf`, etc.

### Shiprocket Dashboard

**Label Download:**
- Individual download from shipment details
- Batch download: Select shipments → "Download Labels" → Multi-page PDF
- "Print Label" opens browser print dialog

## 4. The Real-World Seller Workflow

### Small Seller (5-10 orders/day)

```
Morning Routine:
1. Open dashboard → See new orders
2. Select all pending orders → Click "Batch Ship"
3. Dialog shows courier rates → Confirm shipping
4. SUCCESS: All shipments created
5. Click "Download Labels" → Multi-page PDF downloads
6. PRINT all pages
7. Pack items, match label to box by Order ID, stick labels
8. Wait for courier pickup (2 PM batch)
9. Courier arrives → Give packages + manifest → Done!
```

### Medium Seller (50-100 orders/day)

```
Throughout Day:
1. Orders come in throughout day
2. Every 2 hours: Batch ship accumulated orders
3. Download labels for that batch
4. Pack and label immediately
5. Multiple courier pickups per day

Key Need: Easy batch label download + clear order identification
```

### Large Seller (500+ orders/day)

```
Warehouse Operation:
1. Orders auto-shipped (Auto-Ship enabled)
2. Labels auto-printed to dedicated printer (webhook-based)
3. Warehouse staff pack from picking list
4. Labels come out of printer, matched by barcode scanner
5. Multiple courier pickups scheduled automatically

Key Need: Printer integration, barcode scanning, zero manual steps
```

### Your Concern:

### Answer: Industry-Proven Solutions

Download 50 labels → 50-page PDF → Each page has ORDER ID prominently at top

### Short Answer: NO! They work together beautifully.

│                                                                             │
│  Step 4: Pack and Label                                                     │
│  └─ Print labels                                                           │
│  └─ Match to boxes by Order ID                                             │
│  └─ Stick labels                                                           │
│                                                                             │
│  Step 5: Courier Pickup (Automatic via cron)                               │
│  └─ Cron schedules pickup                                                  │
│  └─ Manifest generated                                                     │
│  └─ Courier arrives, picks up                                              │
│                                                                             │
│  SELLER'S ONLY MANUAL TASK: Download labels + Pack + Stick                 │
│  Everything else is automated!                                              │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Key Insight: Labels MUST Be Manual (Physical Task)

Even with full automation, someone has to:
1. **Print** the label (physical printer)
2. **Stick** it on the box (physical action)

You can't automate this unless you have:
- Dedicated label printer connected to webhook
- Automated labeling machine

**For 99% of sellers:** Manual batch download is the standard.

## 10. Pickups Section with Scheduled Cards ✅

### Why Store Pickup Batches?

You're right! We need to persist pickup batches in the database so we can:
1. Show a dedicated "Pickups" section with scheduled pickup cards
2. Each pickup card shows its orders + manifest download
3. Track pickup history (completed, failed)
4. Generate analytics (pickups per day, packages per pickup, etc.)

### Database Schema for Pickups

```prisma
model PickupBatch {
  id                String            @id @default(uuid())
  storeId           String
  store             Store             @relation(fields: [storeId], references: [id])
  
  // Pickup Details
  courierCode       String            // delhivery, bluedart, etc.
  courierName       String            // Display name
  scheduledSlot     DateTime          // The slot time (10 AM, 12 PM, etc.)
  pickupLocationId  String?           // Which address
  
  // Shiprocket Response
  pickupToken       String?           // PK-2026-789456 (from Shiprocket)
  manifestUrl       String?           // URL to download manifest PDF
  
  // Shipments in this pickup
  shipments         Shipment[]        // Relation to shipments
  shipmentCount     Int               // Cached count for display
  totalWeight       Float?            // Total weight in kg
  codAmount         Float?            // Total COD amount
  
  // Status Tracking
  status            PickupBatchStatus @default(SCHEDULED)
  scheduledAt       DateTime?         // When cron scheduled this
  pickedUpAt        DateTime?         // When courier picked up
  failedAt          DateTime?         // If failed
  failureReason     String?           // Why it failed
  
  createdAt         DateTime          @default(now())
  updatedAt         DateTime          @updatedAt
  
  @@index([storeId, status])
  @@index([storeId, scheduledSlot])
}

enum PickupBatchStatus {
  SCHEDULED         // Scheduled with Shiprocket, waiting for courier
  PICKED_UP         // Courier has picked up
  PARTIALLY_PICKED  // Some shipments picked, some issues
  FAILED            // Pickup failed
  CANCELLED         // Cancelled by seller
}

// Add relation to Shipment
model Shipment {
  // ... existing fields
  
  pickupBatchId     String?
  pickupBatch       PickupBatch?      @relation(fields: [pickupBatchId], references: [id])
}
```

### When is PickupBatch Created?

```typescript
// In the pickup cron job, after successfully scheduling with Shiprocket:

async function processStorePickupQueue(storeId: string): Promise<void> {
  // Group shipments by courier
  const courierQueues = await redis.keys(`pickup:${storeId}:*`);
  
  for (const queueKey of courierQueues) {
    const [, , courierCode, slot] = queueKey.split(':');
    const shipmentIds = await redis.smembers(queueKey);
    
    // Call Shiprocket to schedule pickup
    const response = await shiprocket.post('/courier/generate/pickup', {
      shipment_id: shipmentIds.map(id => parseInt(id, 10)),
    });
    
    if (response.pickup_status === 1) {
      // Generate manifest
      const manifestResponse = await shiprocket.post('/manifests/generate', {
        shipment_id: shipmentIds.map(id => parseInt(id, 10)),
      });
      
      // CREATE PickupBatch in database!
      const pickupBatch = await db.pickupBatch.create({
        data: {
          storeId,
          courierCode,
          courierName: response.data?.courier_name || courierCode,
          scheduledSlot: new Date(slot),
          pickupToken: response.pickup_token_number,
          manifestUrl: manifestResponse.manifest_url,
          shipmentCount: shipmentIds.length,
          status: 'SCHEDULED',
          scheduledAt: new Date(),
        }
      });
      
      // Link shipments to this pickup batch
      await db.shipment.updateMany({
        where: { shiprocketId: { in: shipmentIds } },
        data: { 
          pickupBatchId: pickupBatch.id,
          status: 'PICKUP_SCHEDULED',
          scheduledAt: new Date(),
        }
      });
      
      // Clear Redis queue
      await redis.del(queueKey);
    }
  }
}
```

## 11. Summary

### Label vs Manifest

| Aspect | Label | Manifest |
|--------|-------|----------|
| **What** | Sticker for package | Summary document |
| **When** | Immediately after AWB | After pickup scheduled |
| **Quantity** | 1 per order | 1 per pickup batch |
| **Download** | Individual or batch | Per pickup batch |
| **Purpose** | Track package | Proof of handover |

### UI Locations

| Document | Where to Download |
|----------|------------------|
| Single Label | Order Details, Shipments row action |
| Batch Labels | Shipments list toolbar (select + download) |
| Pickup Labels | Pickups section → Card → Download Labels |
| Manifest | Pickups section → Card → Download Manifest |

### Workflow

1. Auto-Ship/Batch Ship creates shipments → Labels ready
2. Seller downloads batch labels from Shipments page
3. Seller prints, matches to boxes by Order ID, sticks
4. Cron schedules pickup → **PickupBatch created** → Manifest generated
5. Seller goes to **Pickups section** → Downloads manifest
6. Courier arrives → Handover with manifest

### New Database Model: PickupBatch

- Stores each scheduled pickup as a record
- Links to shipments (1 pickup → many shipments)
- Tracks status: SCHEDULED → PICKED_UP / FAILED
- Stores manifestUrl for easy download

**The only manual steps sellers have:**
1. Download labels (1 click)
2. Print labels (1 click)
3. Match and stick labels (physical)
4. Download manifest (1 click)
5. Print manifest (1 click)
